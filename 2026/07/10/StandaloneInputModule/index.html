UGUI 源码剖析 —— StandaloneInputModule

Created2026-07-10|Updated2026-07-10|UnityUGUI
|Post Views:

StandaloneInputModule 负责处理跟鼠标、手指触摸、键盘导航相关的 PointerEventData 状态维护，同时会跟 ExecuteEvents 交互来下发 PointerEventData 及相关事件

StandaloneInputModule 中通过 ProcessTouchEvents() 和 ProcessMouseEvent() 来分别处理触摸事件和鼠标事件

StandaloneInputModule 通过 pointer_id（或finger_id）在字典 m_PointerData 中维护指针数据，每次对于相关的 id 产生新的 PointerEvent 的时候，会先对 PointerEventData 重置，在指针事件期间，会在各个地方维护 PointerEventData 的状态

Process

Process 是 BaseInputModule 的事件处理逻辑入口，由 EventSystem 进行每帧调度

在 StandaloneInputModule.Process 中，会进行以下操作

  • 派发当前 EventSystem 选中对象的选中刷新事件（currentSelectedGameObject）
  • 通过 ProcessTouchEvents 处理触摸事件，默认会先调用这个
  • 如果没有捕获到触摸数据，则通过 ProcessMouseEvent 处理鼠标事件（if input.mousePresent == true）
  • 最后处理键盘导航相关的事件

我们主要关心 ProcessTouchEvents 和 ProcessMouseEvent 的具体实现逻辑

ProcessTouchEvents

对于每一个触摸点，通过 Input.GetTouch(i) 来获取 Touch 数据，在 Touch 中主要封装了 fingerID、position、TouchPhase等信息。

根据 Touch 数据，通过 GetTouchPointerEventData(Touch input, out bool pressed, out bool released) 获取通用的 PointerEventData，以及当前 Touch 的 pressed 和 released 状态

接着通过 eventSystem.RaycastAll(...) 、FindFirstRaycast(...) 来捕获跟当前 touch 关联的检测结果（raycastResult），这个结果中存储触摸目标对象等数据

最后将剩余数据填充到 pointerData （如pressure、position、delta等）

对于 pressed，如果 PointerEventData 是新建状态(created)，或者 touch.phase 处于起始状态（TouchPhase.Began），则 赋值为 true
对于 released，如果 touch.phase 处于取消(TouchPhase.Canceled)、结束状态(TouchPhase.Ended)，则赋值为 true

在 TouchPhase 的注释中可以看到 TouchPhase 一共有 5 个状态：

  1. Began：手指触摸在屏幕
  2. Moved：手指在屏幕上移动
  3. Stationary：手指长按在屏幕上没有移动
  4. Ended：手指从屏幕上抬起
  5. Canceled：手指的触摸被系统取消跟踪，即虽然手指还接触着屏幕，但是系统已经丢弃了对这个触摸点的跟踪

pressed 和 released 的状态关系着 PointerEventData 上相关联的一系列 UI 对象的事件，代码中 通过 ProcessTouchPress(pointerEventData, pressed, released) 来对 pointerEventData 进行处理

ProcessTouchPress

简单来说，如果 pressed = true，则会处理新旧触摸对象对应的层级链的事件派发。对于旧对象的层级链，会给这些对象派发 PointerMove、PointerExit 事件；对于新对象的层级链，会给这些对象派发 PointerEnter、PointerMove 事件。接着是处理连击计数、指针点击、拖拽状态初始化等业务

在处理层级链事件派发时，有点类似于 ExecuteEvents 的冒泡机制，同样都是自下而上遍历，进行事件下发

不同的地方在于 ExecuteEvents 中，冒泡会在事件被处理完后中断

而 此处对层级链的处理还会跟一个变量 m_SendPointerHoverToParent 有关。若 m_SendPointerHoverToParent = true，事件会一直向上传递直到到达了结束条件；若 m_SendPointerHoverToParent = false，那么情况就会跟常规的冒泡机制一样，即一旦遇到了事件（如 PointerExitHandler）被处理，冒泡就会停止

这个变量 m_SendPointerHoverToParent 定义在 BaseInputModule 基类中，受 BaseInputModule.sendPointerHoverToParent 属性控制，默认值为 true。

在方法 BaseInputModule.HandlePointerExitAndEnter() 中可以看到详细的代码实现，其中可以了解到他们通过 PointerEventData.hovered 来管理当前触摸点相关联的层级链对象。

如果 released= true，则对旧对象派发 PointerUp、PointerClick、Drag、EndDrag、PointerExit等事件

ProcessMouseEvent

类似地，首先根据 pointer_id （默认是0）来获取当前的指针数据、以及指针关联的对象。

对于鼠标，会同时产生三个指针事件（左键、中建、右键），这三个 PointerEventData 相互独立互不干扰。

最后对这三个指针分别处理点击、拖拽等事件（跟TouchEvent类似同样需要对 PointerEventData 相关的层级链对象的切换进行事件派发，见 BaseInputModule.HandlePointerExitAndEnter()

总结

核心概念 关键点
输入类型 触摸（ProcessTouchEvents）+ 鼠标（ProcessMouseEvent）+ 键盘导航
数据维护 通过 m_PointerData 字典维护指针状态，指针 ID 区分不同输入源
按压/释放处理 ProcessTouchPress 管理状态切换（Enter/Exit、Press/Click、Drag）
拖拽处理 ProcessDrag 判断拖拽阈值后分发 BeginDrag/Drag/EndDrag 事件
悬停处理 HandlePointerExitAndEnter 对比新旧 hovered 列表，分发 Enter/Exit 事件
事件分发 最终由 ExecuteEvents 调用目标对象上对应 Handler 接口的方法
m_SendPointerHoverToParent 控制 Enter/Exit 事件是否向父节点继续冒泡

📝 写在最后
StandaloneInputModule 是 UGUI 事件系统的“执行者”，它负责将原始输入（触摸/鼠标/键盘）转化为结构化的 PointerEventData，并通过 ExecuteEvents 驱动整个交互响应。
