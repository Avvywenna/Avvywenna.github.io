UGUI 源码剖析 —— Graphic 核心机制

Created2026-07-01|Updated2026-07-15|UnityUGUI
|Post Views:

一、Graphic 是什么？

在 UGUI 中，Graphic 是所有可渲染 UI 元素的基类。
我们常用的 Image、Text、RawImage 本质上都是一个 Graphic。

作为“图形”，它必须具备三个核心要素：

  • 颜色（Color）
  • 形状（Mesh / 网格）
  • 表面细节（Material）

同时，Graphic 还承担了可交互（如射线检测）和布局容器（可嵌套子 Graphic）的能力。

渲染一个 Graphic 时，引擎会根据其颜色、材质和网格数据，将其绘制到 Canvas 上；若包含子 Graphic，则会递归处理。

二、脏标记（Dirty）与重建（Rebuild）机制

当 Graphic 的上述属性发生变化时，并不会立即重新生成网格，而是通过 “脏标记” 来通知系统需要更新。

UGUI 定义了三种脏标记类型：

触发条件 对应方法 说明
颜色、网格、尺寸变化 SetVerticesDirty() 顶点数据需要重建
材质变化 SetMaterialDirty() 材质需要更新
布局变化（含子元素） SetLayoutDirty() 布局需要重新计算

这些方法被调用后，Graphic 会被添加到 CanvasUpdateRegistry 的 待更新队列 中，而不会立刻执行重建。

📌 去重优化：CanvasUpdateRegistry 内部使用 IndexedSet（有序无重复集合）来存储待更新元素。
因此同一帧内对同一个 Graphic 多次调用 SetVerticesDirty，最终只会被重建 一次。

三、重建的触发时机

所有 UI 重建都集中发生在 每帧的末尾，具体调用链如下：

  1. Unity 引擎在 LateUpdate 之后，调用底层 Native 方法 SendWillRenderCanvases。
  2. 该方法会触发 C# 层的 Canvas.willRenderCanvases 事件。
  3. CanvasUpdateRegistry 监听了该事件，并在事件处理中执行 PerformUpdate() 方法。

💡 强制刷新：也可以通过 Canvas.ForceUpdateCanvases() 同步 触发 PerformUpdate，这通常用于需要在代码中立即获取新布局尺寸的场景，但应谨慎使用，因为会立即产生 CPU 峰值。

四、PerformUpdate 的执行顺序

PerformUpdate 内部严格按照以下阶段进行（通过 CanvasUpdate 枚举控制步骤，实现解耦）：

  1. CleanInvalidItems —— 移除已销毁或无效的元素
  2. Layout Rebuild —— 重新计算布局
  3. Clipping Updates —— 遮罩裁剪更新
  4. Vertex Rebuild —— 顶点网格重建

关键点：布局更新（Layout）永远先于顶点更新（Vertex）。
这意味着如果你在布局更新阶段改变了某个 Graphic 的尺寸，该变化会在同一帧的顶点更新阶段立即生效，而不会延迟到下一帧。

五、优化启示

由于所有脏 UI 会在同一帧末尾集中处理，这可能导致 CPU 峰值，进而引起掉帧。针对这一点，我们可以采取以下优化策略：

1. 分帧处理大量 UI 更新

对于像背包、滚动列表这样包含大量元素的 UI，避免一次性激活或修改所有子项，而是将操作分散到多帧中执行，让每帧只重建一部分。

2. 减少脏标记的产生

  • 使用 MaterialPropertyBlock 来修改颜色，避免触发 SetVerticesDirty。
  • 避免在 Update() 中频繁修改 Text.text 或 Image.color 等属性。
  • 虽然 Graphic 内部会做值相等性校验（相同值不会真正脏），但校验本身也有开销。在上层业务逻辑中，主动进行 id 或数值判断，提前拦截不必要的赋值，是更高效的实践。

3. 控制布局递归

在动态增删列表项时，可以先将父节点 SetActive(false)，完成所有添加后再激活。这样可以将原本分散在两帧（布局→顶点）的重建合并到一次 PerformUpdate 中处理，减少整体耗时。

六、Graphic 的生命周期钩子

OnEnable()

当 Graphic 被激活时，它会：

  • 将自己注册到 CanvasUpdateRegistry
  • 与当前 Canvas 建立关联
  • 调用 SetAllDirty()，触发首次渲染

DoMeshGeneration()

这是实际执行网格重建的方法，流程为：

OnPopulateMesh() —— 由子类重写，填充顶点、UV、颜色等数据
⬇
IMeshModifier 接口 —— 可对顶点数据进行二次修改（如变形、特效）
⬇
canvasRenderer.SetMesh(workerMesh) —— 将最终网格提交给渲染器

七、扩展能力

  • OnPopulateMesh：自定义 UI 组件可重写此方法，手工构建网格数据，实现任意形状绘制。
  • IMeshModifier：实现该接口，可以在网格已经生成后对其进行再加工，常用于实现扭曲、渐变、水波纹等视觉效果。

八、总结

核心概念 关键点
基类 Graphic 是所有 UGUI 可渲染元素的基类
脏标记 SetVerticesDirty / SetMaterialDirty / SetLayoutDirty
去重 IndexedSet 保证同一帧内单元素只重建一次
触发时机 LateUpdate 后 → SendWillRenderCanvases → willRenderCanvases 事件
执行顺序 布局 → 裁剪 → 顶点
优化方向 分帧更新、减少脏标记、控制布局递归
扩展方式 重写 OnPopulateMesh 或实现 IMeshModifier
