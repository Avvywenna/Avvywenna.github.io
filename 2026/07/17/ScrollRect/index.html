UGUI 源码剖析 —— ScrollRect 组件

Created2026-07-17|Updated2026-07-17|UnityUGUI
|Post Views:

一、ScrollRect 是什么？

ScrollRect 是 UGUI 中用于实现滚动视图的核心组件。它提供了三个核心功能：

  1. 滑动条的布局支持：根据内容尺寸动态显示/隐藏滚动条，并自动调整视口（Viewport）尺寸
  2. 交互事件处理：响应拖拽、滚轮等输入
  3. 物理模拟：实现惯性滑动、回弹（Elastic）效果

二、布局重建流程

ScrollRect 同时实现了 ICanvasElement、ILayoutElement 和 ILayoutGroup 接口，在 UGUI 的布局系统中承担了双重角色。

1. ICanvasElement.Rebuild

ScrollRect 通过 Rebuild 方法参与 CanvasUpdateRegistry 的统一重建流程：

  • Prelayout 阶段：缓存滚动条状态相关的数据（是否可见、尺寸等）
  • PostLayout 阶段：更新自身包围盒数据、滚动条的位置和大小

2. ILayoutElement（不参与布局计算）

ScrollRect 虽然实现了 ILayoutElement 接口，但实际上并没有提供有效的布局数据：

  • CalculateLayoutInputHorizontal / CalculateLayoutInputVertical：空实现
  • minWidth / preferredWidth 等属性：均返回 -1

这意味着 ScrollRect 不会主动影响父布局容器的尺寸决策。它的尺寸通常由父布局容器决定，或者由用户手动设置。

3. ILayoutGroup（核心布局逻辑）

ScrollRect 作为布局容器，在 SetLayoutHorizontal 和 SetLayoutVertical 中实现了核心的布局逻辑，主要职责是根据滚动条的显示状态动态调整 Viewport 的尺寸。

SetLayoutHorizontal

SetLayoutHorizontal 处理的是 Viewport 在滚动条显示状态影响下的尺寸调整。其处理流程可以概括为以下步骤：

第一步：更新缓存数据

调用 UpdateCachedData，更新当前滚动条的状态：

  • 水平滚动条是否动态显示（m_HorizontalScrollbar != null && m_HorizontalScrollbarVisibility == ScrollRect.ScrollbarVisibility.AutoHide）
  • 垂直滚动条是否动态显示（m_VerticalScrollbar != null && m_VerticalScrollbarVisibility == ScrollRect.ScrollbarVisibility.AutoHide）
  • 水平滚动条的尺寸（m_HorizontalScrollbarWidth）
  • 垂直滚动条的尺寸（m_VerticalScrollbarWidth）
  • 滚动条与 Viewport 之间的间距（m_HSliderSpacing / m_VSliderSpacing）

第二步：让 Viewport 完全覆盖可用区域

将 Viewport 的 anchorMin 设为 (0, 0)，anchorMax 设为 (1, 1)，sizeDelta 设为 Vector2.zero。此时 Viewport 完全贴合父容器，没有为任何滚动条预留空间。

为什么用 sizeDelta 而不是直接设置 size？因为 anchorMin 和 anchorMax 设置为 (0,0,1,1)，sizeDelta 的值表示包围盒与父容器边界的距离，默认描述的是包围盒的宽高。当 sizeDelta = Vector2.zero 时，表示完全贴合父容器；当 sizeDelta.x < 0 时，表示在宽度上留出了空间。

第三步：第一次强制重建

调用 LayoutRebuilder.ForceRebuildLayoutImmediate(content)。因为 Viewport 尺寸变化后，其内部的 Content（以及 Content 内部的子元素）可能受到自动布局组件（如 ContentSizeFitter）的影响，尺寸会发生变化。这个调用确保在后续判断滚动条是否需要显示时，Content 的尺寸是最新的。

第四步：处理垂直滚动条的动态显示

如果满足显示条件（Content 的高度 > Viewport 的高度，至少相差 0.01），则修改 Viewport 的 sizeDelta.x 减去垂直滚动条的宽度和间距（m_VSliderWidth + m_VerticalScrollbarSpacing），为垂直滚动条留出空间。

第五步：第二次强制重建

再次调用 LayoutRebuilder.ForceRebuildLayoutImmediate(content)。因为 Viewport 宽度减小后，Content 的宽高可能也会随之变化（如果 Content 上挂了自动布局组件），需要再次确认 Content 的最终尺寸。

第六步：处理水平滚动条的动态显示

如果满足显示条件（Content 的宽度 > Viewport 的宽度，至少相差 0.01），则修改 Viewport 的 sizeDelta.y 减去水平滚动条的高度和间距（m_HSliderHeight + m_HorizontalScrollbarSpacing），为水平滚动条留出空间。

第七步：对垂直滚动条的兜底处理

这是一个边界情况：如果一开始 Content 的高度不足以触发垂直滚动条显示，但是在处理水平滚动条时，水平滚动条占用了 Viewport 的高度，可能导致 Viewport 高度变小，从而使得 Content 的高度 > Viewport 的高度——此时垂直滚动条的条件被“触发”了。

因此最后需要再检查一次垂直滚动条是否应该显示，如果应该显示但之前没有处理过，则再调整一次 Viewport 的宽度。

简单理解：这个流程是在反复执行“让 Viewport 填满 → 检查是否需要滚动条 → 需要的话留出空间 → 再检查另一边是否也因此需要滚动条”的循环，直到所有滚动条的显示状态都确定下来。

SetLayoutVertical

SetLayoutVertical 处理的是滚动条本身的尺寸调整：

  • 根据滚动条的显示状态，分别调整水平滚动条和垂直滚动条的 RectTransform 尺寸
  • 由于滚动条本身占用了一些空间，对于另一侧的滚动条，需要在初始尺寸下扣除被占用的那一部分

例如，如果垂直滚动条可见，水平滚动条的总宽度需要减去垂直滚动条的宽度，防止两者重叠。

为什么用 ForceRebuildLayoutImmediate？

SetLayoutHorizontal 中调用了两次 ForceRebuildLayoutImmediate（第一次在初始化 Viewport 后，第二次在调整垂直滚动条后）。这个调用是同步的，会立即完成布局计算，而不是等到下一帧的 PerformUpdate。

原因是：在 SetLayoutHorizontal 执行过程中，后续的判断（如“Content 的高度是否超过 Viewport”）需要依赖最新的 Content 尺寸。如果不立即重建，Content 的尺寸还是旧值，判断就会出错。

这也是 ForceRebuildLayoutImmediate 的一个典型使用场景——当需要在同一帧内获取布局后的尺寸时，必须立即执行重建。

三、拖拽与滚动交互事件

ScrollRect 通过实现 IBeginDragHandler、IDragHandler、IEndDragHandler 和 IScrollHandler 来响应指针交互。

1. 拖拽事件（Drag 系列）

OnBeginDrag

初始化拖拽相关的数据：

  • 记录拖拽开始时的指针位置
  • 记录 Content 的当前位置
  • 缓存当前的包围盒数据（m_ViewBounds 和 m_ContentBounds）
  • 重置惯性速度（如果正在减速，立即停止）

OnDrag

将指针位移应用到 Content 的位置上，即 Content 跟随指针移动。

但这里会根据 MovementType 的不同，对位移做不同的处理：

MovementType 行为
Unrestricted Content 完全跟随指针，没有边界限制
Elastic Content 跟随指针，但当 Content 超出 Viewport 边界时，会产生“被拉住”的感觉，超出越多阻力越大
Clamped Content 跟随指针，但严格限制在 Viewport 边界内，不会超出

具体的实现方式是：先计算 Content 位置 = 初始位置 + 指针位移，然后计算 Content 与 Viewport 之间的偏移量（Offset），即 Content 超出 Viewport 边界的距离：

  • Unrestricted：忽略偏移量
  • Elastic：将偏移量通过一个曲线函数（ScrollRect.RubberDelta）修正后再加到 Content 位置上，产生阻力效果
  • Clamped：直接将偏移量限制到 0，即不允许任何超出

OnEndDrag

  • 重置拖拽标志（m_Dragging = false）

2. 滚轮事件（IScrollHandler.OnScroll）

滚轮事件不涉及指针位置，因此 Content 的位移直接由滚轮的滚动值决定：

position += scrollDelta * scrollSensitivity

其中 scrollDelta 来自 PointerEventData.scrollDelta，通常 y 分量代表垂直滚轮，x 分量代表水平滚轮（如果有水平滚轮的话）。

与拖拽类似，Clamped 模式下会对 Content 的位置进行边界限制。

四、物理模拟

ScrollRect 的物理模拟在 LateUpdate 中实现，主要处理三种情况：

1. 回弹（Elastic）

当拖拽结束，Content 处于“不完全覆盖 Viewport”的状态（即 Content 有一部分在 Viewport 之外），且 MovementType = Elastic 时，Content 需要回到完全覆盖 Viewport 的位置。

核心实现：Mathf.SmoothDamp 方法，它会根据起始值、目标值、当前速度、平滑时间等参数，计算出一个平滑的插值结果，从而实现“回弹动画”。

2. 惯性滑动

当拖拽结束，Content 的速度不为 0，且开启了惯性（m_Inertia = true）时，Content 会继续沿当前方向滑动，并逐渐减速到 0。

核心实现：

velocity *= Mathf.Pow(m_DecelerationRate, Time.deltaTime)

m_DecelerationRate 是一个小于 1 且大于 0 的系数（默认是 0.135），Mathf.Pow(m_DecelerationRate, deltaTime) 会随着 deltaTime 的增加而减小，使得速度按指数衰减。当速度小于 1.0 时，会被强制设置为 0，停止滑动。

3. 拖拽过程中的速度计算

在拖拽过程中，如果开启了惯性，ScrollRect 会实时计算 Content 的当前速度：

velocity = (content.anchoredPosition - m_PrevPosition) / Time.deltaTime

其中 m_PrevPosition 是上一帧 Content 的位置。这个速度值会在 OnEndDrag 之后作为惯性滑动的初始速度。

五、重要成员方法

1. UpdateBounds

UpdateBounds 是 ScrollRect 中一个核心但容易被忽略的方法，它的作用是：以 Viewport 为参考系，计算 Content 和 Viewport 的包围盒（Bounds）。

什么是包围盒（Bounds）？

Bounds 是一个通过中心位置和宽高来在空间中确定一个矩形区域的工具。Bounds 是轴对齐的，即使 UI 元素发生了旋转，Bounds 也能计算出将其完全包含在内的最小轴对齐区域。

m_ContentBounds 的计算方式：

  1. 获取 Content 的四个顶点在世界空间中的坐标
  2. 将这四个顶点从世界空间转换到 Viewport 的局部空间
  3. 遍历这四个局部坐标，从中选出 minX、maxX、minY、maxY，构成包围盒

m_ViewBounds 的计算方式： 会直接以 Viewport 自身的 中心点、尺寸来创建。

AdjustBounds 的作用：

计算完成后，ScrollRect 会调用 AdjustBounds 将 m_ContentBounds 调整到至少和 m_ViewBounds 一样大。这一步的目的是简化边界计算——例如在判断“Content 是否完全覆盖 Viewport”时，通过两个包围盒的边界大小比较，可以判断是否完全覆盖，从而触发后续的边界修正（Clamped、Elastic等）。

需要注意：对包围盒的修改不会影响 Content 的实际尺寸，只是用于计算和判断。

Clamped 模式下的特殊处理：

如果 MovementType = Clamped，AdjustBounds 还会将 m_ContentBounds 调整到与 m_ViewBounds 重合的位置（如果 m_ContentBounds 偏离 m_ViewBounds 的话）。

ScrollRect 中对content位置的计算几乎都依赖这两个包围盒，大体上会先计算当前状态下的包围盒，然后进行各种情景处理后，最后将包围盒的数据应用到本体上。

2. CalculateOffset

CalculateOffset 是一个辅助方法，用于计算 m_ContentBounds 是否完全覆盖 m_ViewBounds，并返回两者之间的偏差向量。

它的返回值的含义：

  • 如果 Vector2.zero：Content 完全覆盖 Viewport
  • 如果 x < 0：Content 在水平方向上向右侧偏移了 -x 距离
  • 如果 x > 0：Content 在水平方向上向左侧偏移了 x 距离
  • 垂直方向同理

这个偏差值在 OnDrag 和 LateUpdate 中被广泛使用，用于计算 Content 的位置修正量。

六、性能注意事项

  1. ForceRebuildLayoutImmediate 的成本：SetLayoutHorizontal 中调用了两次强制重建，每次都会遍历 Content 下的所有子元素计算布局，对于列表项很多的情况，会有性能开销。这种成本主要发生在布局变化时，但不会在滚动的每一帧都发生。

  2. LateUpdate 中的计算：即使 ScrollRect 处于静止状态，LateUpdate 中的判断（检查速度是否为 0）也会被执行。如果场景中有大量的 ScrollRect，这可能会有累积开销。

  3. 内容更新时的重建：当 Content 中的子元素数量变化时（如动态增删列表项），需要调用 SetDirty 触发布局重建，否则 ScrollRect 的包围盒不会更新，滚动条的显示状态可能不正确。

七、总结

核心概念 关键点
角色 滚动视图组件，支持滑动条的动态布局、拖拽交互和物理模拟
布局角色 实现 ILayoutGroup，动态调整 Viewport 尺寸以适配滚动条显示
布局策略 Viewport 先填满 → 判断垂直滚动条 → 留空间 → 判断水平滚动条 → 兜底处理垂直滚动条
交互事件 实现 IDragHandler 和 IScrollHandler，响应拖拽和滚轮
MovementType Unrestricted / Elastic / Clamped，分别对应“无限制”、“回弹”、“严格限制”
物理模拟 LateUpdate 中实现惯性减速（DecelerationRate）和回弹（SmoothDamp）
包围盒计算 UpdateBounds 计算 m_ViewBounds 和 m_ContentBounds，以 Viewport 为参考系
性能注意 ForceRebuildLayoutImmediate 的调用成本和 LateUpdate 的持续执行
