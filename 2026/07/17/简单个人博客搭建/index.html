一些碎碎念

前排提醒本篇内容只针对系统Windows 11，不涉及其他系统

在前段时间在查资料，碰巧点进了某位大佬的个人博客，精致的布局和炫丽的背景令人眼前一亮，网页主题简洁、美观且实用，随后萌生了如果自己也有一个属于自己的这样的二次元小窝（×）就好了的想法。

当我漫无目的地翻阅着的时候，在早期发布的帖子中翻到了关于博客搭建的分享，通过这篇文章我了解到原来搭建这个博客意外的方便，并没有我印象中的复杂（例如要自己部署服务器，自己写html、css等，我猜的）

后来我依葫芦画瓢地也弄起了属于自己的博客网站。

本站采用了Hexo博客框架 + GitHub Pages部署的方式搭建，所需的工作和环境：

  • NodeJs
  • Hexo
  • Git
  • Github

关于这套搭建框架，在网上随便都能找到很多类似的，不过很多时候自己按照别人的流程来走的过程中，或多或少会碰到别人没有提及的问题，每当这种时候确实会很无力

所以说，以下内容是我个人做法和踩坑的记录，希望对你有所帮助

NodeJs

关于NodeJs，感兴趣的自行了解

在本篇中，Hexo依赖NodeJs的环境来构建、运行网页，另外NodeJs在安装时会自动安装npm，正好是我们所需要的，例如我们需要使用npm来安装、初始化我们的Hexo项目

点击NodeJs官方下载页面，选择下载Windows系统的.msi程序并安装，在安装程序中一路选择Next直到安装结束

在命令行窗口中执行以下命令查看是否安装成功

Github

GitHub 注册和登录

如果你是第一次使用GitHub，需要先注册并登录

Github有时候裸连会不太稳定，如果遇到网络问题，可以试试Watt Toolkit免费的GitHub加速工具，或者考虑科学上网

GitHub 新建仓库

Hexo博客的部署需要我们准备两个GitHub仓库

在GitHub首页，点击创建仓库（Respository）。

第一个是用于管理项目源文件的仓库

该仓库主要负责管理你的文章原稿、草稿以及网站配置等资源，所以推荐将仓库可见性设置为Private

选择勾选创建ReadMe文件，来使仓库初始状态不为空，至于其他选项可以保持默认

确认无误后，点击 Create repository 完成创建

第二个是用于部署网站的仓库

关于GitHub仓库是如何被用于部署网站的，可以点击这里了解

回到首页点击创建仓库

根据GitHub Pages的使用规范，我们需要将仓库的名称命名为USERNAME.github.io，USERNAME替换为你的GitHub用户名，例如我的GitHub用户名是Avvywenna，那么这里的仓库命名就是avvywenna.github.io（主要大小写替换）

然后选择仓库可见性为Public（默认就是）

最后点击Create repository 完成创建

四、Hexo 项目结构（可跳过）

初始的项目文件夹结构如下

.
├── .github
|   └── dependabot.yml
├── _config.yml
├── .gitignore
├── package.json
├── scaffolds
├── source
|   └── _posts
├── node_modules
├── public
└── themes

.github

这是一个跟GitHub相关的目录，用于项目的自动化管理

默认状态下.github内还有一个dependabot.yml，是用于给Hexo项目自动打理项目的依赖更新、版本管理等

在后续内容中，我们也会在.github内部署我们自己的工作流配置，用于Hexo的自动化构建部署

_config.yml

Hexo基础样式配置文件，以下是一些比较常用的配置项

# Site 站点配置
Title: 博客主页大标题/浏览器页签主标题
subtitle: 浏览器页签副标题
description: 博客主页的介绍，通常是一些作者个人介绍或者博客介绍等
author: 博客作者
language: 站点语言，如zh
timezone: 站点时区

# URL 
url: 站点首页链接，在我们的GitHub Pages完成部署后，可以将可访问链接填在这个位置（这会在很久之后）

# Extensions 站点扩展
theme: 博客使用的主题，在本篇中，我们会使用butterfly作为博客的样式主题

除了上述我提到的字段外，Hexo还有其他很多的自定义内容，更详细的介绍请移步官方文档。

.gitignore

Git会无视记录在.gitignore文件里的文件的修改

package.json

站点的应用程序信息文件，记录了网站的基础信息、项目的依赖管理等，大多数情况下无需我们关心

scaffolds

当你通过Hexo指令新建帖子时，Hexo 会从 scaffolds 中选择一个md模版进行创建，这个模版默认是post，也可以指定特定模版

例如通过以下命令使用 photo 作为模版新建一篇文章，并且命名为”My Gallery”

在执行这行指令时，Hexo 会尝试在 scaffolds 文件夹中寻找 photo.md，并根据其内容建立文章。

scaffolds内置了三种模版：post、page 和 draft。其中post是默认模版。

source

source是存放我们文章的地方，初始状态下该目录下只有一个 _post 子目录

当我们以 post 模版新建帖子时，被新建的文件会被放在 _post 目录下

在 _post 目录中的内容会在 hexo 构建的时候发布到 public 中，然后可以在站点内访问

除了 _post 目录外，还有一些我们会用到但是没有被默认创建的目录

  1. _draft

    当我们以 draft 模版新建帖子时，被新建的文件会被放在 _draft 目录下，在这里的内容通常被视为草稿，不会被hexo处理

  2. categories

    categories目录赋予站点可按分类检索内容的机能，相当于给站点添加一个分类的板块

    在categories目录下，新建文件index.md，其内容如下

  3. tags

    跟categories类似，使用方式移步至这里

node_modules

node_modules 文件夹是 npm 通过 npm install 自动生成的目录，用于存放项目所依赖的所有第三方模块（包）
Hexo 在执行 hexo g（生成静态文件）或 hexo s（启动本地服务器）时，会从 node_modules 中加载所需的模块代码
在版本控制（如 Git）中，一般会忽略 node_modules（通过 .gitignore），因为其内容可以根据 package.json 和 package-lock.json 通过 npm install 重新生成

public

Hexo在构建启动时会在public目录里生成网页代码和资源，可以理解为网页本身

theme

不同的网页主题脚本存放于此，在构建时Hexo根据配置的主题来生成静态页面

五、Hexo的美化

Butterfly是一个简洁的、卡片式UI设计的Hexo网页主题。在Butterfly官网 - 快速开始，可以找到非常详细的部署教程

稳定版下载

打开命令行窗口，来到博客项目的根目录，从GitHub下载稳定版主题项目

应用主题

修改_config.yml里的主题为 butterfly

安装渲染插件

打开命令行窗口，来到博客项目根目录，安装主题渲染所需组件

至此主题部署完成，在themes\butterfly\下的_config.yml中可以对美化主题进行自定义设置，之后重新构建启动 hexo 即可

当需要升级主题时，可以在themes\butterfly内通过git pull更新

由于我们可能会修改butterfly内的_config.yml，所以在拉取的时候会发生冲突，需要我们选择要保留的部分来解决冲突

优化主题升级（可跳过）

  1. 在博客项目根目录下新建文件 _config.butterfly.yml
  2. 将themes/butterfly/下的_config.yml的内容拷贝到 _config.butterfly.yml
  3. 所有主题配置的修改都在 _config.butterfly.yml 进行

Hexo在构建时会合并 _config.butterfly.yml 和主题自己的 _config.yml，对于同名的配置会优先采用前者

六、GitHub Pages部署

GitHub仓库关联

我们之前创建了两个仓库，一个 Private 仓库以及一个 Public 仓库，Private 仓库用于管理我们博客项目源文件，Public 仓库用于部署站点

现在我们可以来继续完成这两个仓库的配置和部署了

首先将本地的博客项目提交到 Private 仓库，你可以在网上找到相当多的教程，例如这是我找到的一篇关于如何将本地项目上传到GitHub仓库

然后以下是我自己的做法（仅供参考）

找到 Private 仓库，复制其链接：https://github.com/Avvywenna/for-test.git

打开命令行窗口，来到空文件夹内， 执行 git clone https://github.com/Avvywenna/for-test.git

将博客项目的内容全部拷贝到for-test文件夹内，然后进入到 for-test/themes/butterfly/ 将.git删掉（这是因为git会将其识别为第三方的 Git 仓库会产生警告，如果不想处理的话就直接删掉 .git，但是会导致后续无法通过 git 更新版本）

回到命令行窗口，将for-test内新增内容同步到GitHub

GitHub Pages配置

接着对第二个 Public 仓库配置，我们要在 Public 仓库上开启 GitHub Pages 的功能

找到 Public 仓库，在 Settings 处找到 Pages 设置项

将部署来源 Source 设置为 Deploy from a branch，将部署分支来源 Branch 保持为 None

部署分支来源是由GitHub Actions自动创建的分支，目前还没有激活GitHub Actions的功能，所以这里还不存在这样的分支

GitHub Actions配置

关于GitHub Actions

第一步、创建GitHub Token

点击创建一个GitHub Token，用于赋予GitHub Actions的生效范围和权限，这里需要在 Select scopes 勾选 repo 和 workflow

点击 Generate token 完成创建

根据提示，请务必将生成的Token拷贝保存好（复制到其他你能随时找到的地方）

第二步、创建Respository secret

打开 Private 仓库，在 Settings - Security - Security and variables 处，选择 Actions，点击 New respository secret

在 Name 处填 HEXO_DEPLOY（任意有意义的名称，后续需要用到）

在 Secret 处填刚刚保存下来的 Token 字符串

点击 Add secret 完成创建

第三步、创建 Actions 配置文件

注：下面需要在 Git 仓库内创建文件，你可以直接在 GitHub 上在线创建，也可以在本地博客项目创建，然后通过 git 提交到 GitHub

在 Private 仓库根目录创建 .github\workflows\，.github 是项目自带的，因此只需要再创建一个 workflows 目录，接着在 workflows 文件夹下创建 hexo-deploy.yml 文件

在 hexo-deploy.yml 中，我们引用了第三方的 Actions 配置：theme-keep/hexo-deploy-github-pages-action@master，这是一款专门将 Hexo 部署到 GitHub pages 的 Actions

确保你的修改都提交到 GitHub，后续在 main 分支修改源文件时（可以在线修改，或通过 Git 提交），会自动触发上述配置的 GitHub Actions 工作流，它会对 Hexo 重新构建，然后推送到 Public 仓库的 gh-pages 分支（会自动创建），最后 GitHub Pages 会将仓库的内容部署为网站，并可以通过它提供的地址访问

你需要完成至少一次Commit来启动 GitHub Actions，这样在 Public 仓库中才会被创建 gh-pages 分支

博客网站部署

回到 Public 仓库，在 Settings - Pages 页面，将 Branch 设置为 gh-pages

如果一切正常，你就可以通过https://????.github.io/来访问，此处的 ????.github.io 是你的 Public 仓库名称，实际上在 Pages 页面也有相关的内容描述

关于在 GitHub Pages 中使用自定义的域名，可以在互联网上查找相关资料了解，这里不作为重点介绍

关于异常

有可能到最后你并无法成功访问到自己的博客，可能有以下一些原因

  • hexo-deploy.yml 配置文件填写错误、格式错误

    这种情况需要检查内容是否确认无误，另外也需要确认缩进是否正确

  • Actions 构建报错
    这种情况我遇到的比较少，需要根据具体问题去查找解决办法，它可能是由于 Respoitory secret 配置错了、相关名称拼写错了等导致的

  • 构建成功，但是网站访问不到
    一种可能的情况是 Public 仓库的名称没有跟 GitHub 用户名保持一致（除了大小写）

  • 如果遇到更多的问题，相信你静下心来一定能找到解决办法的
