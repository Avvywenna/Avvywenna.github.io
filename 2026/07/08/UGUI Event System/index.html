UGUI 源码剖析 —— EventSystem 事件系统

Created2026-07-08|Updated2026-07-10|UnityUGUI
|Post Views:

EventSystem 是 UGUI 事件系统的 总调度中心，负责协调输入模块、射线检测器和事件分发，是整个交互模块的“发动机”。

一、整体架构

事件系统由三个核心部分组成：

  1. EventSystem + InputModule：调度层，驱动事件循环，管理输入处理策略
  2. Raycaster：检测层，执行实际的射线检测，找出命中的 GameObject
  3. ExecuteEvents：分发层，将事件数据发送给目标对象上实现了对应接口的组件

层级关系

EventSystem 本身不实现射线检测算法，也不实现具体的事件分发逻辑，它的核心职责是：

  • 持有并调度当前激活的 BaseInputModule
  • 作为 RaycastAll 的入口，遍历所有已注册的 BaseRaycaster

一句话定位：EventSystem 是“总指挥”，Raycaster 是“侦察兵”，ExecuteEvents 是“传令兵”。

二、EventSystem 与 InputModule

一个场景中通常只有一个 EventSystem 实例。它通过挂载 BaseInputModule 的派生类来支持特定平台的输入处理。

InputModule 的核心方法

方法 职责
UpdateModule() 更新输入模块自身的状态，处理模块的启用/禁用切换
Process() 当前帧输入事件的主入口，由 EventSystem.Update() 每帧调用

调度方式

EventSystem.Update() 只驱动当前激活的 currentInputModule：

currentInputModule.Process()

多个 InputModule 并存的意义在于 按需切换（如编辑器下手动切换 Standalone/Touch 模块）。实际项目通常只使用 StandaloneInputModule，它内部通过 ShouldActivateModule() 自动适配鼠标或触摸输入，因此能同时覆盖 PC 和移动端。

三、完整事件流程

从鼠标点击到 UI 响应的完整链路如下：

  1. EventSystem.Update() 在每帧调用当前 InputModule 的 Process() 方法
  2. StandaloneInputModule.Process() 处理当前帧的输入事件（按下、抬起、移动、滚轮等），调用 EventSystem.RaycastAll() 获取命中目标
  3. EventSystem.RaycastAll() 遍历场景中所有已注册的 BaseRaycaster，调用其 Raycast() 方法收集命中结果
  4. GraphicRaycaster.Raycast() 执行实际射线检测，遍历 GraphicRegistry 中注册的 Graphic，进行矩形碰撞检测和 ICanvasRaycastFilter 过滤
  5. 排序筛选：返回的 RaycastResult 列表按深度、sortingOrder、renderOrder 等规则排序，取第一个作为最终命中目标
  6. ExecuteEvents.Execute 将事件分发给目标 GameObject 上的对应 Handler 组件（如 IPointerClickHandler）

四、GraphicRaycaster 与 GraphicRegistry

GraphicRaycaster 不能脱离 Canvas 独立存在，它依赖于 Canvas 组件来获取该 Canvas 下的所有可交互 Graphic。

GraphicRegistry 的数据结构

GraphicRegistry 内部维护了一个字典，用于快速查找：

Dictionary<Canvas, IndexedSet<Graphic>>

  • IndexedSet 保证了元素的 唯一性 和 稳定遍历顺序
  • 每个 Graphic 在 OnEnable 时将自己注册到所属 Canvas 的集合中
  • GraphicRaycaster.Raycast() 直接从该集合中获取目标列表

Raycast 命中判定的几个关键步骤

  1. 检查点击位置是否在 Graphic 的矩形范围内
  2. 检查 Graphic 的世界坐标是否在事件相机的视口平面内
  3. 检查 Graphic.raycastTarget 是否为 true
  4. 调用 ICanvasRaycastFilter.IsRaycastLocationValid() 进行精细过滤（如 Image 的透明像素检测）

五、排序规则

GraphicRaycaster.Raycast() 返回的结果列表按以下优先级排序：

  1. Camera.depth: 若两个射线结果来自不同的事件相机，则按相机的渲染顺序降序排序（depth更大的排在前）
  2. Raycaster.sortOrderPriority: 若两个射线结果来自不同的Raycaster，则按各自的sortOrder降序排序（sortOrder更大的排在前）
  3. Raycaster.renderOrderPriority: 若两个射线结果来自不同的Raycaster，则按各自的renderOrder降序排序（renderOrder更大的排在前）
  4. sortingLayer：按 sortingLayer 降序排序（sortingLayer值更大的排在前）
  5. sortingOrder：若 Canvas 启用了 overrideSorting，按此降序排序（sortingOrder更大的排在前）
  6. Graphic.depth：按图形在同一个Canvas内相对深度降序排序（depth更大的排在前）
  7. distance：按照目标距离射线起点的相对距离升序排序（distance更小的排在前）
  8. index：按射线结果本身的index顺序升序排序（index更小的排在前）

最终 InputModule 取列表第一个元素作为命中目标。

六、事件分发机制（ExecuteEvents）

ExecuteEvents 首先声明了一个委托类型 EventFunction

在这个委托中它需要两个参数，第一个是泛型（IEventSystemHandler），第二个是 BaseEventData

此处泛型的作用是为了实现将不同的 EventFunction 实例绑定到对应的 Execute(T, BaseEventData) 方法

例如对于拖拽事件，通过这样的方式创建一个用于调用 OnDrag 接口的委托实例

ExecuteEvents 中的核心方法是

  • ExecuteHierarchy(GameObject root, BaseEventData eventData, EventFunction callbackFunction)
  • Execute(GameObject target, BaseEventData eventData, EventFunction functor)

ExecuteHierarchy 自下而上遍历 root 层级链，逐一调用 Execute，直到 Execute 返回 true

Execute 首先通过 GetEventList 获取 target 上跟泛型匹配的 IEventSystemHandler，对于每一个 handler，将其转换为 EventFunction<T> 对应的类型 T 实例（如 IDragHandler ），然后调用 functor 完成派发

此处的 functor 就是一开始提到的一系列 Execute 重载中的一个

例如一个关于拖拽事件的派发调用链如下：

ExecuteHierarchy(root, eventData, EventExecutes.s_DragHandler) -> Execute(target, eventData, functor) -> functor(handler, eventData) -> handler.OnDrag(eventData)

冒泡机制

ExecuteEvents.ExecuteHierarchy 在执行事件分发时，会从目标 GameObject 开始，沿父节点链向上遍历（bubble-up），查找挂载了对应 Handler 接口的组件并调用其接口。这一机制允许父节点统一处理子节点无法处理的事件（如 ScrollRect 的拖拽事件）。

七、ICanvasRaycastFilter

这是一个在射线检测最后阶段进行精细控制的接口：

bool IsRaycastLocationValid(Vector2 screenPoint, Camera eventCamera)

在源码中对 ICanvasRaycastFilter 的处理有一个令人在意的地方：对于一个 graphic，代码会一直向上查询它的 parent，对于它的 parent 如果身上存在 ICanvasRaycastFilter 并且该组件判定为无法处理事件时，对于一开始的 graphic 来说也会被判定为无法处理事件，就算 graphic 自身的ICanvasRaycastFilter是通过的。

例如场景中有 Image A 和 B，其中 B 在 A 里面，此时由于 A 启用了透明度过滤的参数导致在 Sprite 的透明区域无法接收事件时，就算实际上是点击到 B 身上，对于 B 来说也是无法接收到事件的。

这种效果类似于 A 是作为一个事件遮罩存在，作用是屏蔽不在 A 遮罩范围内的事件，例如 CanvasGroup。

八、总结

核心概念 关键点
整体架构 由EventSystem进行模块驱动，由Graphic进行射线检测，由EventExecutes进行事件分发
事件数据结构 PointerEventData
InputModule 对具体输入事件数据进行整理、处理的终端
GraphicRegistry 维护 Canvas → Graphic 的映射，支持快速查询
