UGUI 源码剖析 —— RawImage 组件

Created2026-07-14|Updated2026-07-14|UnityUGUI
|Post Views:

一、RawImage 是什么？

RawImage 是 UGUI 中用于直接显示 Texture 的组件。与 Image 不同，它不依赖于 Sprite 和 SpriteAtlas，而是直接引用一个 Texture 对象（可以是 Texture2D、RenderTexture 等）。

它的设计目的就是针对纯粹的绘制需求：把一张贴图原样显示在 Canvas 上。因此，它不支持九宫格、平铺、填充等复杂的渲染模式，也没有 Image 那样丰富的交互和布局功能。

适用场景：

  • 背景图层（不需要交互）
  • 临时的 Texture 显示，如从网络下载的图片
  • 视频画面（RenderTexture）
  • 程序化生成的纹理

从源码来看，RawImage 的代码量大约是 120 行左右（相比之下 Image 有约 1200 行），可见其功能定位是“精简、直接”。

二、RawImage 的继承关系

RawImage 同样继承自 MaskableGraphic，因此它：

  • 会参与到 CanvasUpdateRegistry 的统一重绘流程
  • 支持 RectMask2D 和 Mask 的遮罩效果
  • 不会自动参与布局系统（没有实现 ILayoutElement）
  • 没有实现 ICanvasRaycastFilter，所以无法像 Image 那样做基于透明像素的点击过滤

RawImage 和 Image 是同级关系，都继承自 MaskableGraphic，但它们在功能丰富度上有明显的差异。

三、核心参数 —— uvRect

RawImage 在 Inspector 上暴露的核心参数比较少，其中最主要的就是 uvRect。

这是一个 Rect 类型的参数，默认值是 (0, 0, 1, 1)。它代表纹理坐标的映射范围，控制 Texture 的哪一部分被显示在 UI 区域中。

通过修改 uvRect，可以实现一些简单的效果：

  • 显示纹理的局部区域：比如只显示一张大图中的某个小区域（类似 Sprite 的裁剪效果，但不需要图集）
  • 平面动画（Sprite Sheet 效果）：通过程序在运行时修改 uvRect 的 x 或 y 偏移量，逐帧切换显示的纹理区域，实现类似帧动画的效果

举个例子，如果有一张包含 4 帧动画的纹理（2x2 排列），可以每帧切换 uvRect：

第 1 帧：uvRect = new Rect(0, 0.5, 0.5, 0.5)
第 2 帧：uvRect = new Rect(0.5, 0.5, 0.5, 0.5)
第 3 帧：uvRect = new Rect(0, 0, 0.5, 0.5)
第 4 帧：uvRect = new Rect(0.5, 0, 0.5, 0.5)

这里的 uvRect 是 UV 空间中的坐标，范围是 0 到 1。需要注意，纹理坐标的原点是左下角，而不是左上角。如果纹理的坐标系是左上角原点（比如某些从网络下载的图片），在使用 uvRect 时可能需要翻转 y 轴。

四、OnPopulateMesh —— 网格填充

RawImage 的 OnPopulateMesh 实现非常简单，它不区分任何模式（没有 Image 那样的 type 枚举），只做一件事：

给 VertexHelper 填充四个顶点，构成一个四边形。

这四个顶点的坐标由 RectTransform 的绘制区域决定，而纹理坐标则直接使用 uvRect 的值。

对应的顶点顺序是：左下、左上、右上、右下，纹理坐标依次映射为：

  • 左下：(uvRect.xMin, uvRect.yMin)
  • 左上：(uvRect.xMin, uvRect.yMax)
  • 右上：(uvRect.xMax, uvRect.yMax)
  • 右下：(uvRect.xMax, uvRect.yMin)

然后绑定两个三角形（[0,1,2] 和 [0,2,3]），完成网格填充。

对比 Image 的 OnPopulateMesh，RawImage 的这一实现大约只有 30 行左右，可以说是极简的。

五、关于合批的说明

源码注释中有一句话提到，每个 RawImage 可能会产生额外的 drawcall。这句话的本意是警告开发者不要滥用 RawImage，因为如果每个 RawImage 都使用不同的纹理，它们会各自独立渲染，导致 drawcall 线性增长。

但这里需要明确一点：RawImage 并不是完全无法合批的。

根据 UGUI 的合批规则，在同一个 Canvas 下，如果两个相邻的 UI 元素使用了相同的纹理，它们就有可能被合批。因此，以下两种情况是可能发生合批的：

  • 两个 RawImage 引用了同一张纹理
  • 一个 RawImage 和一个 Image 使用了同一张纹理（但注意 Image 需要将纹理导入为 Sprite，而 RawImage 直接引用 Texture）

不过在实际项目中，这种情况比较少见，因为：

  • RawImage 通常用于显示独立的纹理资源（如网络图片、视频），这些资源一般不会和其他 UI 共用纹理
  • 如果多个 RawImage 共用同一张纹理，理论上可以合批，但它们需要满足深度排序相邻的条件

所以更准确的说法是：RawImage 不参与图集，因此合批难度更高。在大多数实际使用场景中，每个 RawImage 确实会独立产生 drawcall，但这不是绝对的，合批与否取决于具体使用的纹理和排序条件。

六、对比总结：Image vs RawImage

维度 Image RawImage
数据源 Sprite Texture（Texture2D / RenderTexture 等）
图集合批 ✅ 支持（通过 SpriteAtlas） ❌ 不支持（独立纹理）
渲染模式 Simple / Sliced / Tiled / Filled 仅简单四边形
九宫格 / 平铺 / 填充 ✅ 支持 ❌ 不支持
uvRect 控制 通过 Sprite 的 UV 间接控制 ✅ 直接控制 uvRect
透明点击过滤 ✅ 支持（ICanvasRaycastFilter） ❌ 不支持
参与布局系统 ✅ 实现 ILayoutElement ❌ 不参与
适用场景 常规 UI（按钮、图标、面板等） 非常规纹理（视频、摄像头、网络图片、RenderTexture）
性能特征 图集优化，合批友好 独立纹理，易增加 drawcall

七、使用建议

  1. 优先使用 Image：在常规 UI 开发中，应该优先使用 Image，配合 SpriteAtlas 来优化合批性能。
  2. RawImage 用于特殊需求：只有确实需要显示独立的 Texture（如网络图片、RenderTexture、视频帧）时，才使用 RawImage。
  3. 背景图层可以放心用：如果 RawImage 作为全屏背景且只出现一次，不会对整体性能造成明显影响。
  4. uvRect 可以做简单动画：利用 uvRect 做纹理偏移或帧动画时，注意 UV 坐标系的原点在左下角。

八、总结

RawImage 是 UGUI 中功能最精简的 Graphic 组件之一。它的设计思路是 “直接、轻量、无依赖” ：直接显示一个 Texture，不依赖 Sprite 和图集，也不提供复杂的渲染模式。

这种设计的代价是合批不友好和功能有限，但换来的优势是使用灵活，能够覆盖 Image 无法处理的场景（如动态纹理、视频画面等）。理解它的实现原理，有助于在实际项目中根据需求做出正确的选择，避免为了省事而用 RawImage 替代 Image，导致性能问题。

本文为个人学习总结，如有不准确之处，欢迎指正交流。
