UGUI 源码剖析 —— Mask 组件

Created2026-07-04|Updated2026-07-06|UnityUGUI
|Post Views:

一、Mask 是什么？

Mask 是 UGUI 中用于实现 任意形状裁剪 的组件。与 RectMask2D 不同，Mask 不局限于矩形区域，可以配合任意 Image 或 RawImage 的网格形状（如圆形头像、星形图标）进行裁剪。

Mask 的实现依赖于 GPU 的 模板缓冲（Stencil Buffer），这也是它与 RectMask2D 在性能特征上截然不同的根本原因。

二、Graphic 的材质管理机制

在理解 Mask 之前，需要先了解 Graphic 的材质管理机制，因为 Mask 正是通过修改 Graphic 的材质来工作的。

Graphic 内部维护了两个材质相关的成员：

  1. 默认材质（只读）：通过 Canvas API 获取的通用 UI 材质（如 UI/Default），不可修改。
  2. 自定义材质（可写）：用户通过 Graphic.material 属性设置的材质。

当访问 Graphic.materialForRendering 时，获取顺序如下：

  • 优先返回用户设置的 自定义材质（如果有）
  • 否则返回 默认材质

获取到基础材质后，Graphic 会检查自身所在的 GameObject 上是否挂载了实现了 IMaterialModifier 接口的组件，并按顺序依次调用 GetModifiedMaterial 方法，对材质进行 链式修改，最终得到用于渲染的材质实例。

Mask 正是 IMaterialModifier 的一种实现。

三、Mask 的 GetModifiedMaterial 流程

Mask.GetModifiedMaterial 的核心逻辑可以拆解为以下几个步骤：

第一步：找到主导排序上下文的 Canvas

从当前 Mask 节点向上遍历，找到最近的、能够决定渲染顺序的 Canvas。这个 Canvas 将作为模板缓冲操作的“上下文容器”。

第二步：计算模板深度值

从当前 Mask 节点开始，向上遍历到该 Canvas 节点，统计路径上遇到的 所有 Mask 组件数量（不包括自身，从 0 开始计数），作为模板深度值（Stencil Depth）。

模板深度的 上限为 8。如果嵌套超过 8 层，UGUI 会输出警告并限制最大深度为 8。这是因为 Unity 的模板缓冲通常使用 8 位整数（0~255），而 Mask 使用 1 位来表示一个 Mask 层级，因此最多支持 8 层嵌套。

第三步：将深度值转换为二进制掩码

将模板深度值 d 转换为二进制数：

1 << d

例如：

  • d = 0 → 1（二进制 00000001）
  • d = 1 → 2（二进制 00000010）
  • d = 2 → 4（二进制 00000100）

这个二进制数用于计算模板测试的 参考值（Reference Value），用于区分不同层级的 Mask。

💡 巧妙之处：使用二进制位移可以同时支持多层 Mask 嵌套。当多个 Mask 叠加时，每个 Mask 占用一个独立的二进制位，互不干扰。这样在渲染时，可以精确控制哪些区域被特定层级的 Mask 裁剪。

第四步：生成两个材质实例

根据二进制掩码，Mask 会生成（或从缓存中复用）两个材质实例：

材质 模板测试操作 用途
写入材质（Write Material） 模板测试始终通过，将模板值写入缓冲 在渲染 Mask 的 Graphic 图形时，将当前 Mask 的模板值写入 Stencil Buffer
恢复材质（Restore Material） 模板测试根据掩码匹配，恢复之前的模板状态 在渲染完被遮罩的子元素后，清空或恢复该 Mask 占用的模板位

这两个材质会通过不同的 API 设置到 CanvasRenderer 中：

  • SetMaterial：设置 写入材质，用于渲染 Mask 自身的图形
  • SetPopMaterial：设置 恢复材质，用于在渲染完成后恢复模板缓冲状态

四、Mask 的完整渲染流程

当 Canvas 执行合批和渲染时，带有 Mask 的子树的渲染流程如下：

  1. 写入阶段：GPU 渲染 Mask 自身的 Graphic（如 Image 的网格），同时将模板值写入 Stencil Buffer。此时模板缓冲中记录了该 Mask 覆盖的区域。
  2. 渲染子元素：子 Graphic 的材质模板测试被配置为“仅当模板值与当前 Mask 的掩码匹配时才通过”，因此只有位于 Mask 区域内的像素才会被渲染。
  3. 恢复阶段：渲染完成后，SetPopMaterial 指定的恢复材质被执行，清除该 Mask 写入的模板值，恢复模板缓冲到之前的状态，为同级或父级的其他 Mask 让路。

子元素如果是 MaskableGraphic，那么同样会通过 GetModifiedMaterial 生成用于模板测试的材质，如Image、RawImage等。

这也是为什么一个 Mask 组件会产生额外的 DrawCall：

  • 写入阶段至少 1 个 DrawCall（渲染 Mask 自身图形）
  • 恢复阶段至少 1 个 DrawCall（清除模板状态）
  • 子元素的 DrawCall 视具体内容而定，但它们都受到模板测试的约束

考虑有三个Mask嵌套的情况，此时对应的模板缓冲变化是这样的

除了第一个遮罩外，其余遮罩掩码计算公式为 desiredStencilBit | (desiredStencilBit - 1)

例如 当 desiredStencilBit = 00000010 时，模板掩码 = 00000011

  • 首先从上到下它们的（desiredStencilBit） 分别是 00000001、00000010、00000100
  • 对于第一个遮罩，它所覆盖范围内的缓冲值是 00000001，在缓冲恢复时，清空模板缓冲的设置
  • 对于第二个遮罩，它所覆盖范围内的缓冲值是 00000011，在恢复缓冲时，将缓冲区的值设置为 00000001 （desiredStencilBit - 1）
  • 对于第二个遮罩，它所覆盖范围内的缓冲值是 00000111，在恢复缓冲时，将缓冲区的值设置为 00000011 （desiredStencilBit - 1）

这三个遮罩的渲染顺序为：

Mask 0 写入缓冲 00000001
Mask 1 写入缓冲 00000011
Mask 2 写入缓冲 00000111
..
Mask 2 恢复缓冲 00000011
Mask 1 恢复缓冲 00000001
Mask 0 恢复缓冲 清空

可以看到每次遮罩完成了自己的测试之后，会通过PopMaterial恢复到上一个遮罩设置的缓冲值，使用二进制掩码的设计使得这种操作完美契合

五、Mask 的优缺点

优点

  • 支持任意形状裁剪：Mask 的裁剪区域由 Graphic 的网格决定，因此可以配合任意 Sprite 形状（如圆形、星形、文字轮廓）实现遮罩。

缺点

  • 额外 DrawCall 开销：每个 Mask 组件至少增加 2 个额外的 DrawCall（写入 + 恢复），多层嵌套开销叠加。
  • 打断合批：由于 Mask 的子节点使用了不同的模板测试状态，它们无法与外部同材质纹理的 UI 元素合批。
  • 模板缓冲深度限制：最多支持 8 层 Mask 嵌套，超过限制会触发警告。
  • 边缘锯齿问题：Mask 的裁剪结果是“像素完全显示或完全丢弃”，不会混合边缘像素的颜色，因此遮罩边缘容易出现锯齿，尤其在对角线或曲线边缘较为明显。

六、边缘锯齿问题详解

边缘锯齿问题，根源在于模板测试的 离散性：

  • 模板测试的本质上是一个 二元判断：像素在遮罩区域内（通过）或不在（丢弃）。
  • 它不会像 Alpha Blend 那样对边缘像素进行颜色混合，因此无法产生平滑的过渡效果。
  • RectMask2D 的边缘锯齿相对不明显，是因为矩形边界天然与像素网格对齐；而 Mask 常用于圆形或不规则形状，斜线或曲线边缘的锯齿会更明显。

常见解决方案：

方案 实现方式 适用场景
使用 SoftMask 插件（第三方库） 通过 Alpha 测试替代模板测试，在 Shader 中实现软边缘 需要高质量遮罩效果的项目
增加遮罩图形的分辨率 使用更高分辨率的 Sprite，减少像素块感 静态遮罩
手动在遮罩图形边缘添加半透明像素 在图片边缘预制渐变透明度 简单场景

七、Mask 与 RectMask2D 的深度对比

特性 Mask RectMask2D
裁剪形状 任意形状（由 Graphic 网格决定） 仅矩形
实现原理 模板缓冲（Stencil Buffer） Shader 矩形裁剪
额外 DrawCall +2（写入 + 恢复） 0
打断合批 是 否
嵌套深度限制 最多 8 层 无限制
边缘质量 容易产生锯齿 相对平滑（因矩形对齐）
适用场景 圆形头像、不规则遮罩 列表滚动、矩形裁剪区域

八、IMaterialModifier 链式调用

上文中提到的 IMaterialModifier 是一个值得展开的设计模式。

当多个 IMaterialModifier 同时挂载在同一个 GameObject 上时（例如同时存在 Mask 和某个自定义材质修改器），UGUI 会按照 组件在 Inspector 中的顺序 依次调用 GetModifiedMaterial，形成一个 责任链（Chain of Responsibility）：

原始材质 → IMaterialModifier A → IMaterialModifier B → … → 最终材质

这种设计使得材质修改逻辑可以 灵活组合，而不需要修改 Graphic 自身的代码。

九、潜在性能陷阱

在实际项目中，Mask 的使用容易踩到以下陷阱：

  1. Mask 嵌套过深：每层 Mask 都增加额外的 DrawCall，超过 8 层还会触发警告和截断。
  2. Mask 节点下的 Graphic 触发材质实例化：由于 Mask 会为每个子 Graphic 修改材质，可能导致大量材质实例被创建，增加内存占用。
  3. 频繁启用/禁用 Mask：Mask 的启用和禁用会触发其下所有 Graphic 的材质重新计算，可能引起短暂的性能峰值。

十、总结

核心概念 关键点
实现原理 模板缓冲（Stencil Buffer），通过 IMaterialModifier 修改材质
模板深度 从 0 开始计数，上限为 8 层嵌套
二进制掩码 1 << depth，用于区分不同层级的 Mask
材质实例 写入材质（SetMaterial）+ 恢复材质（SetPopMaterial）
额外开销 每个 Mask 至少 +2 DrawCall，且打断合批
边缘锯齿 模板测试是二元判定，无像素混合
适用场景 任意形状遮罩，需配合 Graphic 网格
与 RectMask2D 对比 更灵活，但性能开销更大

📝 写在最后
Mask 是 UGUI 中“灵活性换性能”的典型代表。
理解其模板缓冲的实现原理，可以帮助你在实际项目中做出更合理的权衡：

  • 矩形裁剪 → 优先用 RectMask2D
  • 不规则形状 → 使用 Mask，但要注意嵌套深度和边缘质量
  • 高质量不规则遮罩 → 考虑第三方方案（如 SoftMask）
