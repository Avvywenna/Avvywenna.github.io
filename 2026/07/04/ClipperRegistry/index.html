UGUI 源码剖析 —— ClipperRegistry 与 RectMask2D

Created2026-07-04|Updated2026-07-06|UnityUGUI
|Post Views:

一、ClipperRegistry 是什么？

ClipperRegistry 是 UGUI 中用于管理 “可裁剪对象” 的中央注册表。它的核心职责是：

  1. 收集：管理所有实现了 IClipper 接口的实例（如 RectMask2D），在它们启用时注册，禁用时注销。
  2. 调度：在 PerformUpdate 的“裁剪更新”阶段，通过 Cull 方法遍历所有注册的 IClipper，触发它们的裁剪计算。

与 CanvasUpdateRegistry 不同，ClipperRegistry 不涉及脏标记或队列。它是一个简单的“快照式”注册表——每当需要执行裁剪时，直接遍历当前注册的所有 IClipper，逐一调用其 PerformClipping 方法。

ClipperRegistry 本身是一个单例，通过静态实例 s_Instance 访问。

二、生命周期与触发时机

ClipperRegistry 的触发时机与 CanvasUpdateRegistry 紧密相关：

  • 在 CanvasUpdateRegistry.PerformUpdate() 的 布局重建（Layout Rebuild） 和 图形重建（Graphic Rebuild） 之间，会调用 ClipperRegistry.Cull()。
  • 这个位置是固定的：布局完成后，网格生成前。

为什么裁剪更新在这个位置？

  • 布局阶段确定了每个 UI 元素的 最终尺寸和位置。
  • 裁剪阶段需要基于这些尺寸计算出每个元素的 有效可见区域。
  • 图形阶段在生成网格时，会直接应用裁剪区域数据，决定哪些顶点被保留或剔除。

因此，裁剪更新必须发生在 布局之后、图形之前。

三、RectMask2D 的裁剪流程

RectMask2D 是 UGUI 中最常用的裁剪组件。它的裁剪流程完全通过 ClipperRegistry.PerformClipping 驱动，具体步骤如下：

第一步：收集有效遮罩列表

RectMask2D 在执行裁剪时，会收集所有 能够影响自身裁剪效果 的祖先 RectMask2D。收集规则如下：

  • 从当前 RectMask2D 节点开始，向上遍历父节点。
  • 如果遇到祖先节点上也有 RectMask2D 组件，则将其加入列表。
  • 关键规则：如果从当前节点到某个祖先节点之间存在一个 Canvas 组件，且该 Canvas 的 overrideSorting 为 true，则该祖先节点（以及更上层的）RectMask2D 不会被加入列表。

为什么 overrideSortingOrder 会阻断遮罩传递？

当 Canvas.overrideSortingOrder = true 时，该 Canvas 会创建一个独立的排序上下文，其子元素的渲染顺序完全由该 Canvas 的 sortingOrder 决定，与父级 Canvas 无关。这种“排序上下文隔离”也意味着 裁剪上下文被隔离——父级 RectMask2D 无法穿透这个 Canvas 影响其子元素。

第二步：计算最终有效矩形

收集到所有祖先 RectMask2D 后，将它们各自的 矩形区域（Rect） 进行 交集运算，得到一个最终的 有效裁剪矩形。

  • 如果某个祖先遮罩的矩形与当前遮罩的矩形 不相交，则最终有效矩形为 空（无效）。
  • 如果最终有效矩形无效（如 xMin > xMax 或 yMin > yMax），则后续裁剪不会产生任何可见区域。

第三步：屏幕空间与视口裁剪

在计算最终矩形后，RectMask2D 会进一步检查该矩形是否在屏幕范围内：

  • 如果当前 Canvas 的渲染模式为 ScreenSpaceOverlay 或 ScreenSpaceCamera，裁剪矩形会与 屏幕矩形（Viewport） 进行裁剪。
  • 如果矩形与屏幕没有重叠区域，则整个区域不可见，后续图形重建可直接跳过。
  • 这一步骤的目的是 剔除完全处于屏幕外的 UI 元素，避免浪费性能。

第四步：分发裁剪数据

最终计算出的有效裁剪矩形会被分发到所有受该 RectMask2D 影响的 MaskableGraphic（如 Image、Text、RawImage 等）。分发过程如下：

  • RectMask2D 内部维护了一个 m_ClipTargets 列表，存储所有注册到自身的 MaskableGraphic。
  • 每个 MaskableGraphic 在 OnEnable 或父级变化时，会向上查找最近的 RectMask2D 并注册。
  • PerformClipping 遍历 m_ClipTargets，调用每个 MaskableGraphic 的 SetClipRect 方法。
  • SetClipRect 内部调用 canvasRenderer.EnableRectClipping(clipRect)，将裁剪矩形数据设置到 CanvasRenderer 中。

第五步：羽化（Softness）处理

RectMask2D 还支持 羽化（Softness） 效果，即裁剪边缘的渐变过渡。

  • 羽化参数通过 rectMask2D.softness 属性设置，包含水平和垂直两个方向的羽化值。
  • 在 PerformClipping 中，RectMask2D 会调用 canvasRenderer.SetClippingSoftness(softness) 将羽化参数传递到 CanvasRenderer。
  • 注意：羽化参数 仅对当前 RectMask2D 自身生效，不参与祖先遮罩的叠加。如果存在多个 RectMask2D，羽化效果以最近的 RectMask2D 为准。

四、裁剪数据如何传递到 Shader？

在 MaskableGraphic.SetClipRect 中调用了 canvasRenderer.EnableRectClipping(clipRect)，这个调用最终会将裁剪矩形的数据传递到 Shader 中：

  • CanvasRenderer 内部将裁剪矩形转换为一个 4D 向量（xMin、yMin、xMax、yMax 转化为屏幕空间的边界值）。
  • 在渲染时，Unity 的内置 UI Shader（UI/Default）会读取这个向量，并在片元着色器中判断当前像素是否在裁剪矩形内。
  • 如果像素在裁剪矩形之外，则直接 discard（丢弃），不进行任何渲染。

这也是 RectMask2D 比 Mask 性能更好的原因之一：RectMask2D 的裁剪是在 Shader 中通过简单的矩形边界判断完成的（GPU 并行计算），而 Mask 需要操作模板缓冲（Stencil Buffer），涉及额外的渲染 Pass 和状态切换。

五、Mask 与 RectMask2D 的对比

特性 Mask RectMask2D
实现方式 模板缓冲（Stencil Buffer） Shader 矩形裁剪
DrawCall 开销 +2 个额外 Pass（进入/离开遮罩） 无额外 Pass
合批影响 严重打断合批 不打断合批
裁剪形状 支持任意形状（通过 Graphic 网格） 仅支持矩形
性能开销 较高 较低
适用场景 圆形头像、不规则遮罩 列表滚动、矩形裁剪区域

六、自定义裁剪的实现方式

方式一：通过 OnPopulateMesh 修改顶点数据

在继承自 Graphic 的自定义组件中，重写 OnPopulateMesh 方法，在生成网格数据时直接剔除裁剪区域外的顶点。

  • 优点：完全可控，不依赖 Shader
  • 缺点：需要手动处理顶点裁剪逻辑，代码量大

方式二：通过 IMeshModifier 接口

实现 IMeshModifier 接口，在 ModifyMesh 方法中对已生成的网格进行二次裁剪。

  • 优点：不影响原始的 OnPopulateMesh 逻辑
  • 缺点：同样是 C# 层处理顶点，性能开销取决于顶点数量

方式三：自定义材质和 Shader

编写自定义 UI Shader，在片元着色器中实现裁剪逻辑，通过 MaterialPropertyBlock 传递裁剪参数。

  • 优点：GPU 并行处理，性能最佳
  • 缺点：需要 Shader 编程知识，调试相对复杂

七、与 CanvasUpdateRegistry、Graphic 的关系

在 UGUI 的完整重建流程中，ClipperRegistry 的位置如下：

步骤 执行者 产出
1. 布局重建 LayoutRebuilder 确定所有 UI 元素的尺寸和位置
2. 裁剪更新 ClipperRegistry → RectMask2D 计算裁剪矩形，设置到 CanvasRenderer
3. 图形重建 Graphic 生成网格数据，应用裁剪矩形

八、总结

核心概念 关键点
角色 UGUI 裁剪系统的调度中心，管理所有 IClipper
触发时机 PerformUpdate 中，布局重建之后、图形重建之前
数据结构 List<IClipper>，直接遍历，无脏标记机制
核心操作 收集祖先遮罩 → 计算有效矩形 → 分发到 MaskableGraphic
遮罩穿透规则 overrideSortingOrder = true 的 Canvas 会阻断祖先遮罩传递
数据传递 canvasRenderer.EnableRectClipping → _ClipRect 参数 → Shader
软边缘（Softness） 仅对当前 RectMask2D 生效，不参与叠加
与 Mask 对比 RectMask2D 性能更优，但仅支持矩形裁剪

📝 写在最后
ClipperRegistry 和 RectMask2D 的裁剪机制，是 UGUI 性能优化中经常被忽略但十分重要的环节。
理解它如何收集遮罩、计算区域、分发数据，才能在实际开发中合理选择 Mask 还是 RectMask2D，并在自定义 UI 组件时正确地支持裁剪。
