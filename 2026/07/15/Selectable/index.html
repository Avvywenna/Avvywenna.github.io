UGUI 源码剖析 —— Selectable 组件

Created2026-07-15|Updated2026-07-15|UnityUGUI
|Post Views:

一、Selectable 是什么？

Selectable 是 UGUI 中所有可交互 UI 组件的基类。Button、Toggle、Slider、Scrollbar、Dropdown 等都继承自它。

“可以被选择”的意思是：这个 GameObject 可以被 EventSystem.currentSelectedGameObject 持有。这种“选中”在整个场景中同一时间只有一个——即当前被选中的对象是唯一的。

Selectable 提供了三个核心能力：

  1. 状态管理：根据交互事件切换五种状态（Normal、Highlighted、Pressed、Selected、Disabled）
  2. 外观过渡：根据当前状态改变颜色、Sprite 或播放动画
  3. 导航系统：支持键盘/手柄的方向键在多个 Selectable 之间切换焦点

二、Selectable 实现的接口

为了实现上述功能，Selectable 实现了一系列事件接口。这些接口的触发时机和对应的覆写方法如下：

接口 触发时机 Selectable 中的处理方法
IPointerDownHandler 指针按下 OnPointerDown
IPointerUpHandler 指针抬起 OnPointerUp
IPointerEnterHandler 指针进入目标范围 OnPointerEnter
IPointerExitHandler 指针离开目标范围 OnPointerExit
ISelectHandler 被选中（通过导航或点击） OnSelect
IDeselectHandler 被取消选中 OnDeselect
IMoveHandler 收到导航方向输入（键盘方向键） OnMove

当这些事件触发时，Selectable 会更新内部的 currentSelectionState，然后调用 DoStateTransition 方法，根据当前的 Transition 类型（ColorTint / SpriteSwap / Animation）来改变自身外观。

三、状态枚举 —— SelectionState

Selectable 维护了一个枚举类型 SelectionState，表示当前所处的交互状态：

状态 含义 触发条件
Normal 默认状态 没有任何交互，且 interactable = true
Highlighted 高亮 指针悬停，或通过键盘导航聚焦
Pressed 按下 指针在物体上按下
Selected 选中 通过键盘导航或点击被 EventSystem 选中
Disabled 禁用 interactable = false

状态转换的逻辑依赖具体的事件，具体转换逻辑在 currentSelectionState 的getter实现中

  • OnPointerEnter → isPointerInside = true → Highlighted
  • OnPointerDown → isPointerDown = true → Pressed
  • OnPointerUp → isPointerDown = false → Pressed 以外的其他状态
  • OnSelect → hasSelection = true → Selected
  • OnDeselect → hasSelection = false → Selected 以外的其他状态

状态变化最终都会调用 DoStateTransition 触发外观更新。

四、外观过渡 —— DoStateTransition

DoStateTransition 是 Selectable 中处理外观变化的核心方法。它接收一个状态和“是否即时完成”的参数，根据 transition 类型执行不同的逻辑：

1. ColorTint（颜色过渡）

这是默认的过渡方式。

  • 根据状态从 colors 属性中取出对应的颜色值（normalColor、highlightedColor、pressedColor、selectedColor、disabledColor）
  • 如果 instant 为 true，直接应用目标颜色
  • 否则，通过 CrossFadeColor 在 fadeDuration 时间内渐变到目标颜色
  • 内部调用 CanvasRenderer.SetColor 来修改顶点的颜色

补充细节：CrossFadeColor 是 Graphic 上的一个方法，它使用了 Tween 系统来实现逐帧插值。这个操作会生成一个协程/回调，每帧更新 canvasRenderer 的颜色值。

2. SpriteSwap（图片切换）

  • 根据状态从 spriteState 属性中取出对应的 Sprite（highlightedSprite、pressedSprite、selectedSprite、disabledSprite）
  • 找到目标 Graphic（通常是 Image 组件），替换其 overrideSprite
  • instant 参数对此模式无效（因为 Sprite 切换是即时的）

需要注意的是，这里的 overrideSprite 分配是一次性的，不会在状态恢复时自动清理。如果切换后需要恢复，DoStateTransition 会在状态变回 Normal 时主动将 Sprite 设回 null 或原始值。

3. Animation（动画过渡）

  • 根据状态从 animationTriggers 属性中取出对应的 Trigger 名称（normalTrigger、highlightedTrigger、pressedTrigger、selectedTrigger、disabledTrigger）
  • 调用 Animator.SetTrigger(triggerName) 触发对应的动画状态
  • instant 参数对此模式无效

补充细节：Animation 模式依赖于 Animator 组件，在 Awake 中会缓存 Animator 引用。如果目标对象上没有 Animator，该模式会静默失败。

五、导航系统 —— OnMove

OnMove 是 IMoveHandler 接口的实现，处理键盘方向键（或手柄摇杆）的输入。它的核心逻辑是：在给定方向上，从所有 Selectable 中选出“最合适”的一个，然后将选中权转移过去。

步骤 1：确定原点

根据移动方向，在原 Selectable 的边界上选取一个起始点：

  • 向右移动：以右边界中点为原点
  • 向左移动：以左边界中点为原点
  • 向上移动：以上边界中点为原点
  • 向下移动：以下边界中点为原点

步骤 2：遍历候选对象

遍历 s_Selectables（全局 Selectable 列表），计算每个候选对象相对于原点的位置向量 myVector，以及它和移动方向向量 dir 的点积。

点积公式为：dot = Vector2.Dot(vec.normalized, dir)

  • 正值：候选对象在移动方向的前方，是有效的候选
  • 负值：候选对象在移动方向的后方，通常被丢弃

特殊情况：如果 wantsWrapAround 为 true，允许环绕导航——即当移动到边界时，可以从另一侧绕回来。此时负值的点积会被取反，使候选对象也能被纳入考量。

步骤 3：价值衡量

点积值 dot 作为“符合程度”的度量，值越大（越接近 1），表示该物体越符合当前方向的移动期望。

在选择最优候选时，还需要考虑距离：点积相同的情况下，距离更近的优先。因此实际比较的是 dot / myVector.sqrMagnitude 。

步骤 4：转移选中

Selectable.FindSelectable(dir) 返回找到的候选对象，然后通过 Selectable.Navigate 将选中权转移过去：

  • 更新 EventSystem.currentSelectedGameObject
  • 触发旧选中物体的 OnDeselect
  • 触发新选中物体的 OnSelect

如果启用了 Navigation 的 Visualize 模式，可以在 Scene 视图中看到导航的连线，这有助于调试。

这个算法实际上是在二维平面上基于角度和距离做启发式搜索，而不是基于 UI 的树结构。因此它不要求 UI 元素在 Hierarchy 中是兄弟节点，只要在屏幕空间中有位置关系即可。

六、全局管理 —— s_Selectables

Selectable 内部通过一个静态数组 s_Selectables 来维护场景中所有激活的 Selectable 实例。

注册与注销

  • OnEnable：将自身插入到 s_Selectables 末尾，并记录自己在数组中的索引
  • OnDisable：通过交换移除的方式高效删除，而不是直接移除（避免后续元素整体前移导致 O(n²) 复杂度）

交换移除的具体做法是：将待移除元素与数组最后一个元素交换位置，然后缩短数组长度。同时，两个元素的索引都会被更新，确保一致性。

扩容机制

Selectable[] 的默认容量是 10。当 Selectable 数量超过当前容量时，触发扩容：

  • 以当前容量的两倍大小创建新数组
  • 将旧数组内容拷贝到新数组
  • 旧数组不再使用，等待 GC

设计目的

这个全局列表的主要用途是支持导航系统。当用户按下方向键时，Selectable.OnMove 需要快速找到当前聚焦元素周围的所有可选对象，而不是遍历整个场景中的 GameObject。

使用 s_Selectables 相当于维护了一个“可交互元素注册表”，避免了每次导航时都执行 FindObjectsOfType<Selectable>() 的开销。

这种“集中注册”的设计模式在 UI 框架中很常见，它用一个全局容器管理所有同类对象，而不是靠场景遍历。代价是需要在 OnEnable/OnDisable 时维护列表的一致性，以及存在一个容量上限。

七、与 EventSystem 的协作

Selectable 和 EventSystem 之间有双向的交互关系：

  • EventSystem 驱动 Selectable：EventSystem.SetSelectedGameObject 会调用旧对象的 OnDeselect 和新对象的 OnSelect
  • Selectable 驱动 EventSystem：Selectable.Select 会调用 EventSystem.SetSelectedGameObject，将自身设为当前选中

这形成了一个闭环：当用户点击一个 Button 时，IPointerDownHandler 触发 → Selectable.OnPointerDown 调用 EventSystem.SetSelectedGameObject → EventSystem 更新 currentSelectedGameObject → 旧对象失焦(OnDeselect)，新对象获焦(OnSelect)。

八、交互禁用 —— interactable

interactable 是 Selectable 的一个关键开关。当 interactable = false 时：

  • 组件进入 Disabled 状态
  • 外观变为禁用样式（灰色、禁用 Sprite、禁用动画）
  • 但仍会接收事件——这并非通过取消事件订阅实现

具体来说，Selectable 的事件处理方法（如 OnPointerDown）在被调用时，会先检查 interactable：

  • 如果 interactable = true，执行正常逻辑
  • 如果 interactable = false，仍会设置 isPointerDown = true，只不过在后续状态同步时，由于 interactable = false，会优先进入禁用状态

也就是说，interactable = false 的 Selectable 仍然会收到事件，只是它选择忽略这些事件。这种设计的好处是：事件系统不需要额外判断目标是否可交互，而是让组件自己决定如何响应。

副作用是：GraphicRaycaster 不会跳过 interactable = false 的 Selectable（它只检查 raycastTarget），因此禁用的按钮仍然会阻挡射线。

九、与 Button 的关系

Button 是 Selectable 最简单的派生类：

  • 它通过实现 IPointerClickHandler 来响应点击
  • 在 OnPointerClick 中调用 onClick.Invoke()，触发所有绑定的 UnityEvent 回调

由于 IPointerClickHandler 是在 PointerInputModule 中通过 ExecuteEvents.ExecuteHierarchy 分发的，而 ExecuteEvents 会沿 Hierarchy 向上冒泡。这意味着，如果把 Button 组件挂在父节点上，其子节点中的任意 Graphic 被点击时，都有可能触发这个 Button 的点击事件（取决于射线检测的命中顺序）。

十、注意事项

  1. s_Selectables 的遍历：在 OnMove 中会遍历整个 s_Selectables 列表。如果场景中有大量的 Selectable（比如几百个按钮），这个遍历会有一定的性能开销。在键盘导航使用频率高的场景中（如游戏手柄 UI），需要注意这一点。

  2. 禁用状态的射线检测：interactable = false 的按钮依然阻挡射线点击。如果需要让按钮在禁用状态下不阻挡点击，可以同时设置 Graphic.raycastTarget = false。

  3. Navigation 的可视化：在 Inspector 中设置 Navigation 为 Explicit 时，可以手动指定上、下、左、右对应的目标。而 Auto 和 Horizontal/Vertical 模式则使用算法自动寻找。

十一、总结

核心概念 关键点
角色 所有可交互 UI 组件的基类，管理状态和交互
状态枚举 Normal / Highlighted / Pressed / Selected / Disabled
外观过渡 ColorTint（颜色渐变）/ SpriteSwap（图片切换）/ Animation（动画）
导航系统 通过 OnMove 在二维平面上选择最优候选，依赖全局列表 s_Selectables
全局管理 s_Selectables 维护所有激活的 Selectable，支持高效移除
与 EventSystem 交互 双向驱动：EventSystem 设置选中，Selectable 发起选中
禁用处理 忽略事件，但不阻止射线检测
