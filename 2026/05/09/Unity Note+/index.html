StreamingAssets

Unity 项目结构中有一个StreamingAssets目录，放在该目录下的文件不会被打包进AssetBundle，而是会以原始文件的形式放在一个独立位置，可用于游戏运行时加载。在代码中通过Application.streamingAssetsPath获得在各个平台下正确的路径，然后通过WWW类或文件流访问该路径下的文件。

要注意的是WWW类可以访问互联网，也可用于访问本地文件，需要通过 “file://“ + Application.streamingAssetsPath + “/file_name”的形式发起请求，最终会将文件加载到内存中（不同平台的URL格式不一样）

文件流则只需通过Application.streamingAssetsPath + “/file_name”即可访问，与WWW类的区别是文件流不会一次性加载整个文件到内存，而是每次按需读取字节流，适合大文件访问的场景

在 Android 平台中，流文件会被打包到.jar文件中，所以不支持通过File类来访问，只可以使用WWW类

BetterStreamingAsset

BetterStreamingAssets 是一个 Unity 插件，旨在提供一种统一且线程安全的方式来访问 Streaming Assets 目录中的文件。这个插件特别适用于 Android 平台，能够避免使用效率低下的 WWW 函数或嵌入到 Asset Bundles 中的数据。其 API 设计灵感来源于 System.IO.File 和 System.IO.Directory 类，使得操作更加直观易用。

项目亮点

  • 统一接口：基于.NET标准文件系统API，让熟悉C#文件操作的开发者能无缝上手。
  • 线程安全：保证在高性能多人交互场景下的稳定表现。
  • 针对性优化：特别针对Android平台进行了优化，解决了一系列原生方法中的效率瓶颈。
  • 易于集成：多种安装方式，从Unity包管理器到GitHub直接导入，快速融入现有项目。
  • 日志辅助：详细错误报告功能，特别是对Android平台上可能遇到的文件压缩问题的明确提示，便于调试。

Application.Version

Application.version 是应用版本，可以在ProjectSettings - Player里修改。简单理解为不同的应用版本对应不同的安装包，跟应用资源版本是两个概念。

应用版本的更新通常需要重新下载安装包，而资源版本的更新通常只需要在当前应用里下载更新就好了，资源版本是应用用于检查是否有资源更新，如bug修复、资源优化、替换等。

Application.persistentDataPath

游戏应用持久化数据存储路径，该路径指向设备上的公共目录，应用程序的更新、版本迭代不会擦除这个路径上的数据，而用户可以手动擦除。

该路径主要用于存储游戏运行中产生了一些缓存文件、版本文件等。

游戏版本号管理

常见的应用版本号格式形如 x.y.z，其中x、y、z的语义分别对应Major、Minor和Patch，所以版本号也可以写作 major.minor.patch

在不同语境下会对应不同的语义，例如在 C# 的Version脚本中，xyz会分别对应Major、Minor和Build（还有一个额外的Revision），但是基本都遵从这种规则

  • 主版本号 (MAJOR)：重大更新。当游戏发生不兼容的、颠覆性的架构或玩法改动时递增，意味着新版本可能无法与旧版本共存
  • 次版本号 (MINOR)：新功能上线。当增加新玩法、新角色、系统优化等向下兼容的新功能时递增。例如版本从 1.1.0 到 1.2.0
  • 修订号 (PATCH)：日常修复。紧急漏洞修复或进行对玩法无影响的小调整时递增。例如 1.2.0 到 1.2.1 的更新

在核心框架之外，为了更精确地管理，团队还会加入各种“修饰语”：

  • 版本后缀修饰符：用于标识版本所处的开发阶段。常见的有 -alpha（内测）、-beta（公测）、-RC（发布候选）等。例如 1.0.0-beta.2 就表示是 1.0.0 版本的第二个公开测试版
  • 日期或构建号：增加一个时间戳或自增的构建号可以有效区分同一个版本号的不同打包产物，非常适合回溯问题（如 1.0.0-20260101 和 1.0.0-20260102）
  • 游戏特殊约定：一些大型游戏在命名时会融入其独特的生态。例如，《Minecraft》的测试版会使用年份和周数（如 20w06a），而《守望先锋》这类竞技游戏在赛季更新时也会采用特殊标记，以此营造易于玩家识别的品牌印象

单例的设计模式

  • 构造器私有化（防止外部创建实例）
  • 拥有一个全局唯一的静态实例（通过static声明，可以在静态实例声明的时候初始化，也可以在第一次访问的时候初始化）
  • 这个唯一的静态实例只读（只提供getter访问）
